## Individual Falsification Tests

1. **`H-B1-01` (`layout.py:294`, `size26 != 2688` inline image scale)**:
   - *Falsification test*: Render `kindle_tables_images_exam.epub` (`i4_inline`) at Standard step 03 (`42 px, pitch 63`, where `size26 == 2688`) and compare inline image dimensions against device captures. If `i4_inline` at `42 px` scales inline images by `42 / 16 = 2.625` (`size26 / 1024.0`) rather than `1.80`, then `size26 != 2688` is falsified and the difference between `exam2` p40 and `tables_images` is CSS/HTML attribute driven rather than font-size driven.
2. **`H-B1-02`, `H-B1-05`, `H-B1-07`, `H-B1-08`, `H-B1-10`, `H-B1-11` (`page.py` `c.size_px() == 42.0` / `!= 42.0` table guards)**:
   - *Falsification test*: Capture `kindle_tables_images_exam.epub` at Standard step 03 (`42 px, pitch 63`) or `kindle_exam_v2.epub` at Standard (`45 px, pitch 68`). If `tables_images` at `42 px` behaves like `39 px` and `45 px` (not like `exam2`), then the difference comes from the table CSS rules in `tables_images` vs `exam2` (e.g., `table { width: 100% }` or cell padding CSS), not `size_px() == 42.0`.
3. **`H-B1-03` & `H-B1-04` (`page.py:990,992`, `c.size_px() > 46.0` table scale `0.81` / `886.0`)**:
   - *Falsification test*: Capture `kindle_tables_images_exam.epub` at Standard step 05 (`47 px, pitch 71`, `x0=79, right=1001`, `avail_w = 922`) vs Large (`50 px, pitch 82`, `x0=131, right=949`, `avail_w = 818`). If step 05 (`avail_w = 922`) uses `sc_tbl = 0.75` on 4-col tables while Large (`avail_w = 818`) uses `0.692`, the scaling is a pure function of `avail_w / tot_1x`, not `size_px() > 46.0`.
4. **`H-B1-06` (`page.py:1026`, `row_pad = int(0.28 * c.size_px())`)**:
   - *Falsification test*: Measure `row_hs` on `sc_tbl == 1.0` collapsed tables at `size_00` (`34 px` -> predicts `int(9.52) = 9 px`) and `size_07` (`55 px` -> predicts `int(15.4) = 15 px`). Any deviation > 1 px falsifies `int(0.28 * size_px)`.
5. **`H-B1-09` (`page.py:1399`, `-4 if c.size_px() < 40` borderless table bottom offset)**:
   - *Falsification test*: Measure `t1_columns` p2 (borderless 2-col table) at `size_00` (`34 px, pitch 51`, where `extra_lead_px() = 4.79 > 0`) vs `size_01` (`37 px, pitch 56`).
6. **`H-B1-12` (`page.py:1466`, `maxw != 922` block image scale `maxw / 512.0`)**:
   - *Falsification test*: Compare `i2_dims` (explicit `width="..."` attributes) and `i3_shapes` (no `width` attribute, natural PNG dimensions) in `ti_std` (`maxw = 922`): in `ti_std` `i3_shapes` (`p29`), `maxw == 922` and `img_css_w is None`, so `sc = 1.80` is used, whereas in `ti_compact` (`maxw = 1002`) `sc = 1002 / 512.0 = 1.957` is used. Measuring `i3_shapes` across `ti_std`, `ti_compact`, and `ti_large` directly tests whether KRF scales unstyled block images by `maxw / 512` or by DPI scale.
7. **`H-B1-13` (`page.py:1494`, `rem_h >= 1000 and target_h < 1500` tall image fit-to-page clamp)**:
   - *Falsification test*: Test a block image with `target_h = 1600` when `rem_h = 1200` on a non-empty page: if the device still shrinks it to `rem_h` rather than breaking to a new page, the `target_h < 1500` upper bound is falsified.
